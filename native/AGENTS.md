This directory is the native SwiftUI iOS app. The parent repository also retains the previous Expo prototype for reference; Expo navigation and build rules do not apply to this native target.

- Build the project with `npm run native:build`. `native/project.yml` is the source for XcodeGen; do not hand-edit the generated project.
- Keep conversation, composer, voice, session switching, navigation, settings, and pairing in SwiftUI and native Apple frameworks. Embedded WKWebView pages may reuse DSH plugins, trace, context, team, and complex project tools. Do not move core interactions back into a web view or add React Native.
- Web content loads directly over HTTP or HTTPS under `/dsbot/ui/`, using a page-scoped HttpOnly cookie obtained by native pairing authentication at `/dsbot/web/open`. Documents, resources and page RPC/streams require this authentication. The legacy private scheme is retained only for simulator fixtures. Do not add anonymous pages, a general HTTP proxy, or unrestricted DSH RPC forwarding. Web pages must never receive pairing credentials.
- All native API calls and embedded pages use authenticated HTTP/HTTPS. Native live updates use HTTP long polling; do not add a WebSocket transport. Legacy WS/WSS pairing URLs may be normalized to HTTP/HTTPS only as an import migration. Never send pairing credentials in request URLs or logs.
- Preserve the app bundle identifier and signing team when updating an installed app, and keep old Keychain records until migration is durable.
- Keep decoding, Keychain I/O, image preparation, and diagnostics file writes away from the UI thread.
- The sidebar entries, conversation views, right-dock entries and settings sections come from the dsbot plugin (`navigation.get`), which reads DSH's own registries. Do not list DSH features in the app; add a route for a DSH id in `host/native-navigation.mjs` instead. A screen the app draws itself is named by `open.native`; everything else opens as an embedded DSH page named by `open.web`. Fixture data for navigation is generated from the plugin's own routing (see `ReviewNavigation.swift`), never written by hand.
- The page transport carries one upstream stream: a terminal's keystrokes (`web.stream.send`, only for `terminal/attach` on a dock page, validated in `host/native-page-policy.mjs`). Do not widen it into a general uplink. Dock pages alone keep persistent web storage (per computer, `EmbeddedPageStorage`) and may load frames from http(s) sites; every other page starts clean and loads no frames.
- The app has no primary colour. The root `.tint` is the ink, so system controls (menu icons, buttons, alerts) match every icon; do not add `DSBotStyle.blue` to icons, check marks, spinners or text buttons. Blue stays only on the send button, the pairing buttons, running/connecting status, links and the whale.
- The conversation is home (sidebar button left, views/dock menu right). Every other page — DSH's web pages, files, automations — shows only a back button at the top left (plus the page's own action, such as the plugin page's "+"), and the card behind it is white like the page, so no band of the canvas shows around it.
- Explain a control that cannot be used with a popover anchored to it (`.popover` with `.presentationCompactAdaptation(.popover)`), not with `store.notice` or a toast. TipKit is for one-time feature tips, not for explaining a disabled control on every tap. No such hint ships today.
- Secondary text (副文本) is reviewed before it ships: footnotes, subtitles under a row, helper or hint lines, alert and dialog messages, empty-state explanations. Do not add any without showing the owner the exact wording and getting a yes; the owner removed an unrequested footnote and made this a rule. Copy that DSH itself shows (its own labels and counts) is a copy, not new text, but say so.
- A goal is a full-width bar (`GoalBanner`) on its own row above the composer, with a "…" menu to pause/resume, edit and clear; it is never a chip in the project/mode row. The project and mode chips exist only on the new-task page (a conversation nobody has written in yet) and are gone once the first message is sent; a started conversation shows neither and neither can be changed. A blank conversation never appears in the sidebar, not even while it is open.
- DSH's task list (`todos` in the session detail) shows as a folded `TaskPanel` above the goal bar: only "任务" and the counts until it is opened. Its strings are DSH's own.
- The sidebar has one order: newest first, pinned conversations on top (most recently pinned first). The owner dropped manual sorting and drag-to-reorder (DSH keeps a manual order in the window that made it, not on the computer, so there was nothing to sync); do not bring either back, and do not add an ordering menu.
- Press and hold on a conversation row opens the system context menu with the row as a white card above it: 重命名, 置顶 (取消置顶), 归档 (取消归档 on an archived row). There is no 删除: DSH never deletes a session, and the host has no such method; archiving is what it offers and it is recoverable. A new conversation in a workspace starts from the workspace's "…" menu. A pinned row shows the pin (`DSBotPinGlyph`, a 45° push pin traced from the owner's reference; Lucide only has an upright one) where its time would be.
- A held finger (the talk bar) must not write state the chat view observes: its position lives in `VoiceTouch`, held without observing, and only the glow under the finger listens. Anything slow about starting a capture (the recognizer) is prepared off the main thread when the talk bar comes up (`NativeSpeechCapture.prepare`), and the overlay is mounted but invisible until a press so its first frame is already drawn. When the keyboard leaves, the composer is released at once (`KeyboardAvoidance`); only an arriving keyboard waits to settle.
- Do not generate a live pairing code or inject a pairing link into the phone during testing.
- The conversation view is never rebuilt to come back from a page: it stays mounted under DSH's pages and the app's own (`cardContent` in `DSBotRootView`), only hidden, so Back shows it exactly as it was left. Rebuilding it with a long history already there left the scroll position in the middle of a tall row, which is a white screen on the phone (reproduced with `-dsbot-review-heavy-history -dsbot-review-rebuild-chat -dsbot-review-no-appear-scroll`). A history that has to be scrolled to its end when it appears does so through `scheduleLatestScroll`, whose repeated scrolls let a `LazyVStack` settle, never through a single `scrollTo`; `chat.resume` in the log says what the end marker looked like after a sidebar or page closed.
- The conversation runs to the bottom edge of the screen, under the home indicator (`chatBottomInset`). The composer floats 16pt above that edge (`composerBottomMargin`, its side margin) and 8pt above the keyboard. The history blurs away in one strip under the composer (`bottomEdge`), as tall as the composer plus the gap under it and nothing above it: never size that strip from the chrome (notices, the jump button, chips), or it blurs the text above the composer. The sidebar's footer (computer and settings) is glass over the list, with the same blur beneath it; no line or band between them.
- Never read a window's safe area (or any UIKit geometry) inside a SwiftUI layout closure such as a `GeometryReader`'s: the root view stopped updating (the card no longer followed the drawer, the toolbar menu never appeared). `DSBotRootView` reads the home-indicator inset in a task (at launch and when the width changes) and hands it down through state and `\.homeIndicatorInset`.
- Small icons in the transcript use Lucide's scaled stroke (`DSBotIcon(..., scalesStroke: true)`, about 1.2pt at 14pt, as DSH draws them); the 2pt constant stroke is for the 20pt-and-up icons of the toolbar, sidebar and menus. The top blur is `strength: 0.8`.
- While the conversation is on its way (first connect, switching) the chat shows a centred spinner with "正在连接…" under it (`ConversationLoadingState`), not a spinner at the top of the list.
- XCUITest launches the app with `-dsbot-review-no-blur`. The progressive edge blur (`DSBotEdgeBlur`) keeps paused `UIViewPropertyAnimator`s alive, and XCUITest never sees the app as idle while they exist (a single tap waited about 130 seconds). Screenshots and manual use keep the blur.
