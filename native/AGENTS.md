This directory is the native SwiftUI iOS app. The parent repository also retains the previous Expo prototype for reference; Expo navigation and build rules do not apply to this native target.

- Build the project with `npm run native:build`. `native/project.yml` is the source for XcodeGen; do not hand-edit the generated project.
- Keep conversation, composer, voice, session switching, navigation, settings, and pairing in SwiftUI and native Apple frameworks. Embedded WKWebView pages may reuse DSH plugins, trace, context, team, and complex project tools. Do not move core interactions back into a web view or add React Native.
- Web content loads directly over HTTP or HTTPS under `/dsbot/ui/`, using a page-scoped HttpOnly cookie obtained by native pairing authentication at `/dsbot/web/open`. Documents, resources and page RPC/streams require this authentication. The legacy private scheme is retained only for simulator fixtures. Do not add anonymous pages, a general HTTP proxy, or unrestricted DSH RPC forwarding. Web pages must never receive pairing credentials.
- All native API calls and embedded pages use authenticated HTTP/HTTPS. Native live updates use HTTP long polling; do not add a WebSocket transport. Legacy WS/WSS pairing URLs may be normalized to HTTP/HTTPS only as an import migration. Never send pairing credentials in request URLs or logs.
- Preserve the app bundle identifier and signing team when updating an installed app, and keep old Keychain records until migration is durable.
- Keep decoding, Keychain I/O, image preparation, and diagnostics file writes away from the UI thread.
- The sidebar entries, conversation views and settings sections come from the dsbot plugin (`navigation.get`), which reads DSH's own registries. Do not list DSH features in the app; add a route for a DSH id in `host/native-navigation.mjs` instead. A screen the app draws itself is named by `open.native`; everything else opens as an embedded DSH page named by `open.web`. Fixture data for navigation is generated from the plugin's own routing (see `ReviewNavigation.swift`), never written by hand.
- Retained settings pages revalidate their requested section when visible again and when DSH removes the settings modal. Keep observing the modal's parent after initial readiness, confirm the selected registry section before reporting ready, and hide the desktop root beneath DSH's settings portal so a failed market request cannot expose the home screen.
- The interface uses a black, white and gray theme. The root `.tint` is the ink, so system controls (menu icons, buttons, alerts) match the surrounding icons. `DSBotStyle.blue` is the owner's `#4176E6` blue for existing blue details such as pairing, links, the whale and DSH's command tokens; it is not the theme tint. Send and Stop have their own pale-blue background with ink symbols.
- The conversation is home (sidebar button left, views menu right). Every other page — DSH's web pages, files, automations — shows only a back button at the top left (plus the page's own action, such as the plugin page's "+"), and the card behind it is white like the page, so no band of the canvas shows around it.
- Explain a control that cannot be used with a popover anchored to it (`.popover` with `.presentationCompactAdaptation(.popover)`), not with `store.notice` or a toast. TipKit is for one-time feature tips, not for explaining a disabled control on every tap. No such hint ships today.
- Operation results use `DSBotToastOverlay`, placed below the conversation toolbar without participating in the composer or history layout. Reuse the existing result text, show one material-backed message at a time, and allow multiline failures and manual dismissal. Successes dismiss after 3 seconds, information and warnings after 5, and failures after 7 (at least 8 with VoiceOver); replacing a message cancels its old timer. Voice notice observation stays inside `ChatFeedbackOverlay`.
- Secondary text (副文本) is reviewed before it ships: footnotes, subtitles under a row, helper or hint lines, alert and dialog messages, empty-state explanations. Do not add any without showing the owner the exact wording and getting a yes; the owner removed an unrequested footnote and made this a rule. Copy that DSH itself shows (its own labels and counts) is a copy, not new text, but say so.
- A goal is a full-width bar (`GoalBanner`) on its own row above the composer, with a "…" menu to pause/resume, edit and clear; it is never a chip in the project/mode row. Reserve only its folded 44pt height in the bottom inset; expanded text overlays upwards without resizing the history viewport or moving its messages. Offset the task panel and jump button above the expanded goal and extend the continuous material backdrop to cover it. Editing an existing goal opens a native sheet with its current text and Cancel/Save actions; preserve the message draft. The project and mode chips exist only on the new-task page (a conversation nobody has written in yet) and are gone once the first message is sent; a started conversation shows neither and neither can be changed. A blank conversation never appears in the sidebar, not even while it is open.
- Plan mode appears as a checked “退出计划模式” row in the composer's “+” menu, with no separate banner above the input. Successful commands update the selected state immediately and refresh the watch baseline without clearing history or drafts; do not wait for a later conversation snapshot. Successful mode changes do not create composer notices. Compaction progress appears only in its transcript row. Send and Stop use the same pale-blue circle with an ink arrow or square. A running session keeps unsent text; show Send when there is text or a prepared attachment, and Stop when the composer is empty. Sending a follow-up uses the normal send request without stopping the current task.
- Queued messages come from DSH's `inbox.next-turn` projection and share the host's occurrence IDs. One item shows directly; multiple items fold behind DSH's count label. Edit, remove and steer use `session.updateQueue`; editing opens a sheet and preserves the composer draft. Reserve only the folded 44pt height, overlay expansion upwards and move the goal/task/jump controls above it. Do not convert queued messages into sent transcript bubbles before the host admits them. Subscribe to sequenced session control projections as well as history events. Ordinary context injections stay hidden; only Inbox claims that wake a turn create trigger rows. Do not show an unconditional per-turn usage footer.
- Message text uses a native context menu with a highlighted preview and 复制 / 选择 actions; range selection uses a read-only UITextView. Do not restore per-message copy buttons or timestamps. Centered time separators appear at the first dated exchange, on a new local day, or after five minutes without conversation activity; a long assistant turn never splits its own exchange.
- Conversation images are separate rounded thumbnails above the user's text, with a full-screen preview. Load bytes through the authenticated, watched-session `session.attachment` method; keep image decoding and bounded, computer-scoped disk caches in actors. The new-task mode icon uses the original DSH `AgentPreset` asset.
- DSH's task list (`todos` in the session detail) shows as a folded `TaskPanel` above the goal bar: only "任务" and the counts until it is opened, with an ellipsis on the right. Its strings are DSH's own. Match DSH's StateDot marks: green completed dot, breathing rotating ring while active, and gray pending dot. Size the expanded list to its content, capped for internal scrolling. Reserve only the folded 44pt row in the bottom inset; the expanded card overlays upwards without changing the history viewport or reading position. Keep the jump-to-latest button above the expanded card. Task and goal panels blur the history across their side gutters and the gap below. The goal shares one continuous backdrop with the composer, including attachments and multiline drafts, so no clear strip appears between them.
- The sidebar has one order: newest first, pinned conversations on top (most recently pinned first). The owner dropped manual sorting and drag-to-reorder (DSH keeps a manual order in the window that made it, not on the computer, so there was nothing to sync); do not bring either back, and do not add an ordering menu.
- Press and hold on a conversation row opens the system context menu with the row as a white card above it: 重命名, 置顶 (取消置顶), 归档 (取消归档 on an archived row). There is no 删除: DSH never deletes a session, and the host has no such method; archiving is what it offers and it is recoverable. A new conversation in a workspace starts from the workspace's "…" menu. A pinned row shows the pin (`DSBotPinGlyph`, a 45° push pin traced from the owner's reference; Lucide only has an upright one) where its time would be.
- Hold-to-talk state and speech updates must not invalidate the chat view: keep `VoicePressState` and `NativeSpeechCapture` as unobserved references there, observing them only in the voice layer, composer visibility and feedback overlay. `VoicePressSurface` handles UIKit touch events and immediate haptics; compare its touch timestamp only with system uptime. Read published values before capturing them in the voice layer's geometry closure so rendering follows state changes. Prepare the recognizer off the main thread when voice mode opens and start recognition off the main thread; keep the overlay mounted with immediate press feedback. SwiftUI's keyboard safe area moves the composer; keyboard notifications identify transitions without adding a second delayed lift.
- The composer uses `ComposerTextView`, a native editable UITextView with one to five visible lines, a full input hit area and two-way first-responder synchronization. Preserve marked text during Chinese input; only replace unmarked text when its binding actually differs. Key its identity to the conversation and disconnect its delegate before dismantling it. Keep the glass in a noninteractive background. The composer and history are siblings in a ZStack; the native history's bottom content inset reserves the measured folded chrome height. Do not put the editable view inside the history's inset or content.
- Do not generate a live pairing code or inject a pairing link into the phone during testing.
- The conversation view is never rebuilt to come back from a page: it stays mounted under DSH's pages and the app's own (`cardContent` in `DSBotRootView`), only hidden, so Back shows it exactly as it was left. `ConversationHistoryView` retains its native table and the reading position across these overlays; `chat.resume` records the native viewport on return.
- Key the native history table to the computer and conversation identity. Switching conversations replaces the table so a context menu cannot retain the previous conversation's cells after the diffable snapshot becomes empty; returning from an overlay keeps the same identity and table.
- Conversation history uses a native UITableView with reusable UIHostingConfiguration cells and stable occurrence IDs. Keep existing SwiftUI transcript, question and approval views inside those cells, using their intrinsic vertical size so a reconfigured cell does not stretch its content to the previous height. The running status has its own stable native row beneath the growing turn. Reconfigure only changed rows, retain measured heights by occurrence ID after native layout, and preserve a visible row's relative position when older history is prepended. When alignment changes the native offset, lay out the newly visible cells again in the same pass; leaving them for another frame briefly shifts the status row. Use explicit plain-button disclosure headers in hosted rows so a tap expands the intended group instead of selecting the cell. Do not restore a SwiftUI LazyVStack or ScrollViewReader around the history: its estimated heights fought direct content-offset updates, repeatedly jumping between old code blocks and the running reply even when keyboard tests passed. The native table is the only owner of the history's scrolling.
- UIScrollView delegate callbacks own drag completion and the intentional reading/following state. A keyboard-dismissal drag that began while following preserves following; dismissing the keyboard while reading earlier messages preserves that reading position. Anchor the first row that starts within the unobscured reading area, falling back to an intersecting row for a tall message; rows hidden behind the toolbar must not determine the reading position. Keep that anchor in window coordinates across keyboard transitions. The centred jump button follows this state. Resume following only when a user drag reaches the end or the jump button is tapped. Keep raw geometry and row-height caches in the native coordinator, without publishing them to SwiftUI on each frame. Decorative blur overlays must have SwiftUI hit testing disabled as well as UIKit interaction disabled.
- Restore the last conversation, transcript, goal, mode and drafts from the computer-scoped `ConversationStorage` actor before connecting. Build native history items directly from the restored state, so asynchronous restoration invalidates the message content even when its container size stays unchanged. The first available cached content must trigger scroll recovery without waiting for a network response. Refresh in the background, preserve readable history on failed refreshes, and never show the new-task hero while restoring. Persist before backgrounding or switching computers; drain pending writes before removing a computer's cache. Do not cache credentials or pending approvals in conversation snapshots.
- Merge transcripts and project display rows in the ConversationProjector actor. During live-only updates reuse historical rows and rebuild the running turn. Unchanged snapshot fields must not publish changes. Guard asynchronous projection results against computer, session, watch and application revisions, and retry a projection if a history page changed its base while it was preparing. Keep chat.snapshot.prepare and chat.snapshot.apply diagnostics bounded; they contain timings and counts only.
- Unexpected follow/control stream endings and question wait-claim failures emit a watch-scoped `session.watch.failed` event. Invalidate the native connection generation, retain readable history and reconnect; malformed current snapshots are protocol failures. Unwatch requests carry the previous watch ID so late cleanup cannot stop a newer subscription. Missing cache files alone return an empty load; invalid schema, identity, size and image payloads report typed errors with sanitized diagnostic codes. Image failures remain retryable.
- Markdown parsing stays off the main thread. Its bounded cache has a synchronized lookup for already parsed content, so reused native cells render cached Markdown immediately without a plain-text frame of a different height. While a new revision is being parsed, keep the last parsed content visible; switching back to plain text for every incoming revision changes row heights twice and makes the conversation flicker.
- Live reply text uses StreamingReplyText, with paragraph preparation in StreamingReplyFormatting and stable, equatable paragraph views. Preserve all original line breaks and the whole-message copy action. Do not put a growing multi-paragraph live reply back in a single Text: each incoming character reshapes the entire reply on the main thread.
- Keep short conversation content aligned to the top. The native table's content size, bounds and adjusted insets determine the latest offset. While following, correct that offset after native layout, before the frame is displayed, and skip unchanged offsets. Session startup can target the final native row once; routine streaming must not use timed settling retries. Suspend programmatic scrolling between keyboard will-change-frame and did-change-frame notifications and throughout native dragging or deceleration. SwiftUI keyboard safe areas position the composer; the table's content inset reserves the composer exactly once. Never read UIKit geometry inside a SwiftUI layout closure.
- The conversation runs to the bottom edge of the screen, under the home indicator (`chatBottomInset`). The composer has equal 32pt side and bottom margins (`composerSideMargin`, `composerBottomMargin`) and floats 8pt above the keyboard. The history blurs away in one strip under the composer (`bottomEdge`), as tall as the composer plus the gap under it and nothing above it: never size that strip from the chrome (notices, the jump button, chips), or it blurs the text above the composer. The sidebar's footer (computer and settings) is glass over a regular-material backdrop with a soft top fade that stays fully blurred behind the controls and extends under the home indicator; workspace menus must not show through the settings gear.
- Never read a window's safe area (or any UIKit geometry) inside a SwiftUI layout closure such as a `GeometryReader`'s: the root view stopped updating (the card no longer followed the drawer, the toolbar menu never appeared). `DSBotRootView` reads the home-indicator inset in a task (at launch and when the width changes) and hands it down through state and `\.homeIndicatorInset`. Capture drawer position values before entering its GeometryReader, and size the native history from SwiftUI's proposed viewport without consulting the table's intrinsic size; closing the drawer must repaint immediately, before a tap or a keyboard change.
- Goal and queued-message icons use DSH's original `IconGoalOutlineRegular` and `IconQueueOutlineRegular` vectors in the `Goal` and `Queue` template assets, including native menus. Keep the arrow on the goal target and the rounded message bubble; do not substitute generic Lucide icons. Other small icons in the transcript use Lucide's scaled stroke (`DSBotIcon(..., scalesStroke: true)`, about 1.2pt at 14pt, as DSH draws them); the 2pt constant stroke is for the 20pt-and-up icons of the toolbar, sidebar and menus. The top blur is `strength: 0.8`.
- While the conversation is on its way (first connect, switching) the chat shows a centred spinner with "正在连接…" under it (`ConversationLoadingState`), not a spinner at the top of the list.
- XCUITest launches the app with `-dsbot-review-no-blur`. The progressive edge blur (`DSBotEdgeBlur`) keeps paused `UIViewPropertyAnimator`s alive, and XCUITest never sees the app as idle while they exist (a single tap waited about 130 seconds). Screenshots and manual use keep the blur.
- Conversation details use `ConversationAccess` scoped to the current computer and session. History pages prepend at a frozen cursor and merge tool references across page boundaries; subsequent tail snapshots must retain loaded earlier rows. Never replace a historical diff with a comparison against the current filesystem.
- Native questions use the DSH foreground answer waterfall while open and its late-answer API after continuation. Keep desktop and phone answers racing on the same request, release the phone's wait claim when its watch ends, and never abort the parent agent to dismiss the other answer UI. Pending questions, like approvals, must not be persisted in conversation snapshots.
- Performance defaults to compact; only detailed mode adds a completed turn's usage action. Session statistics come from whole-session projections; detailed turn statistics read the complete turn through its event boundary. Hide unavailable token accounting instead of inventing zeros. Retry chains show their latest attempt, matching DSH.
