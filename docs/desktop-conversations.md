## 当前会话查找（2026-11-17）

主人确认 `.local/designs/conversation-find-2026-11-17/` 后实现。看板右侧会话和事项会话弹窗
共用 `use-conversation-find.jsx`：搜索按钮在复制、展开之前；Mac 上用 ⌘F、其他系统用 Ctrl+F
（不是两个都行，主人 2026-11-17 指出 Mac 上 Ctrl+F 也会打开是错的）打开并聚焦输入框，再按快捷键选中关键词。
输入框从标题栏底线垂下：顶边是方的，没有空隙（批准稿里的 8px 空隙在真实界面里会漏出滚动经过的会话内容，
主人 2026-11-17 指为“奇怪的空隙”），阴影只落在下方；右边距 16px 不变。输入后显示匹配计数，Enter / Shift+Enter 或上下箭头
循环定位；Esc 或关闭按钮清除高亮，保留阅读位置。Esc 在 window 的捕获阶段处理，焦点在输入框、会话、输入框按钮或消息框都关闭，
也认 `event.code === 'Escape'`（输入法可能把 Esc 报成 Process 键）；正在组合输入时的 Esc 仍留给输入法取消组合。
主人 2026-11-17 在真实 Desktop 里遇到 Esc 关不掉，隔离 `dsh web` 里从未复现；Desktop 主进程会抢先处理 DSH 已注册的快捷键，原因未确认。搜索或定位期间只有计数处的一个加载图标，
无匹配时禁用导航，不替换原生会话、输入框或草稿。
首次定位从当前阅读区域的消息位置附近开始；无法取得可见消息位置时从最近的命中开始，
避免输入常见关键词后直接跳到最早记录并自动加载整个历史窗口。

`conversation-find.js` 使用当前 retain 引用的公开 `binding.eventSource` 读取已加载的持久消息，
通过已有认证连接的 `remote.session.page` 被动分页读取较早的记录；页大小为 100 条消息，
固定本次日志截止位置，直到历史耗尽。缓存属于该 binding，保存查找所需的文字，不保存附件、
工具参数或完整历史事件，不为了建立索引而把所有旧消息挂进界面。换关键词复用已完成的文字缓存，
新持久消息合入缓存；取消的分页不推进游标，分页没有进展就报错，不自动轮询重试。
