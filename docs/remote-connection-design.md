## 设计目标

- 一个电脑身份、一份配对记录，包含其内网和公网候选地址；同一台电脑不因地址不同出现两次。
- 每次初次连接、重新连接或网络变化时优先探测内网；只有内网无法建立连接时使用公网。
- 探测期间立即显示进度，正常切换线路只更新状态，保留当前会话、阅读位置和草稿。
- 公网地址为选填。只配内网时沿用现有本地连接，不要求配置公网。
- 设备身份以已配对的电脑身份核验，不能只因为某个内网 IP 回应就向其发送配对凭据。
- 配对、会话与页面仍走现有 HTTP/HTTPS；探测不建立 WebSocket，也不开放匿名页面。

## 一个二维码如何包含多个地址

`host/pairing-devices.mjs` 的 `issue({ address, name, addresses })` 只签发一份设备凭据。配对链接保留
`pair`、`computer`、`name`，新增设备探测标识 `device`，并通过重复的 `lan` / `public` 参数携带带类型的候选 HTTP/HTTPS origin。
扫码后先核验内网候选，内网不能建立连接时再试公网；选中线路后完成一次配对，全部地址保存在同一台电脑下。

手机向 `/api/v1/probe` 发送随机 nonce 和设备标识，不带 Authorization、配对凭据或 URL 查询。
电脑用已保存的凭据 SHA-256 摘要作为 HMAC-SHA256 密钥，对版本、nonce、电脑身份和设备标识签名。
手机用自身持有的凭据计算并验证签名；只有证明匹配的地址才会收到认证请求。探测不会提前兑换配对码，
未配对码的十分钟有效期和已撤销设备的限制同样适用；HTTP 重定向不被跟随。

同类地址并行探测，内网单个请求超时为 2 秒，公网为 5 秒；公网探测只在内网候选失败后开始。
身份已核验但连接失败时继续尝试其余候选。电脑生成统一二维码时不要求公网能从电脑自身回环访问，
避免将路由器不支持回环 NAT 误判成手机无法连接。

公网留空时载荷只包含内网地址，手机无法通过这份配置从外部网络连接电脑；之后可补充地址，
但补充地址必须仍指向已配对的同一电脑。更换线路不改变电脑身份、配对关系或当前会话。

## 旧配对迁移

`Computer` 新增的地址数组、设备探测标识与手动编辑标志均可缺省，原有钥匙串记录继续解码。
尚未获得探测标识时，只向原来保存的地址发送认证；认证后的 ready 返回电脑候选地址和当前设备标识，
手机将其和实际选中的地址持久保存，不更换本地电脑 ID 或配对凭据。旧记录原先使用公网时，
同一次升级连接就会核验新获取的内网候选并优先使用。

按电脑身份重复保存的旧记录在读取时合并候选地址，保留当前选中记录的凭据和本地身份。
旧插件的 ready 没有新增字段时继续按原地址连接；需要先让手机成功连上新版插件，才能取得跨地址核验信息。
旧地址已经完全失效、又尚未完成这次迁移的记录无法凭空取得新地址，仍需使用正式配对入口恢复。

## 2026-11-04 蜂窝切换后反复提示连接失败

通过 USB 拉取 build 29 的真机诊断，在 17:18:33–17:26:10（北京时间）内记录到
125 次 `network.path.changed`、129 次连接尝试、68 次连接成功和 61 次连接失败。
多次成功连接后数秒又由网络回调主动断开；失败记录为 `other.1`，
恢复逻辑将非 `DuduFailure` 的错误统一转换为 `CONNECTION_FAILED`。
当前公网 HTTPS 探测可响应，不能将这种持续重连归因于端口未放行。

原因及本轮修复：

- `NWPathMonitor` 原先把每个回调都当作线路变更；改为比较网络可用性及实际承载流量的接口类型，
  相同快照不重新连接。保留第一次快照由启动流程选路、Wi-Fi / 蜂窝切换重新选路的行为。
- 网络回调的 300ms 防抖任务原先一直持有后续连接；新回调取消它时，也会取消正在执行的探测。
  现在防抖结束即释放该任务，后续回调不会取消连接；真正的任务取消单独处理，不转换为连接失败提示。
- 自动恢复和重试只更新连接状态及连接详情中的失败，用户主动重试、配对和操作失败仍保留既有结果提示。
  不改通知外观，也不新增 App 文案。
- 诊断补充候选地址数量、所选线路类型和系统网络错误码；不记录地址、配对凭据或会话内容。

## 2026-11-04 公网认证检查

按所有者要求，在现行公网地址上执行 31 项认证边界检查，全部符合预期；
未使用真实配对凭据、未生成配对码、未执行业务写入。

- 原生连接、断开、事件长轮询、RPC 及图片读取：无凭据或错误 Bearer 返回 401；
  伪造内网转发头或提交页面 Cookie 不能代替原生认证。
- `/web/open`：无凭据 / 错误凭据返回 401，带跨站 Origin 的打开请求返回 403。
- 页面文档、静态资源、RPC 和流：缺少页面 Cookie 或 Cookie 错误返回 401；
  Bearer 不能代替页面的独立 Cookie。服务端按页面保存随机 Cookie 摘要，
  客户端安装 `HttpOnly` 且以单页路径为作用域的 Cookie，HTTPS 时标为 `Secure`。
- 根路径、通用 DSH RPC 与非页面作用域的静态资源返回 404；不开放通用 DSH 转发。
- `/api/v1/probe` 的无设备 nonce 探测按设计公开，只返回协议版本和 nonce 绑定的 HMAC 证明，
  不返回配对凭据、会话或文件。不存在的设备标识返回 401。
- HTTPS 的域名与证书链校验通过；Nginx 仅配置 TLS 1.2 / 1.3。
  Nginx 转发保留认证头和 Cookie，不提供绕过上游认证的规则。
- 服务器代理端口 13107 及 FRP 管理端口 17000 绑定 `172.18.0.1`，
  公网连接探测均超时；新 HTTPS 网关仅映射 8443。
