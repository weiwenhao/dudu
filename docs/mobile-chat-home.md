## 数据契约

`board.list {tab, layout: "chat"}` 返回平铺 `conversations`、置顶 `pins` 和 `unreadCount`，旧的分组契约保留给旧客户端。读取所有事项时通过既有分页，不因首 200 条限制漏项。主页只传短摘要，不传事项完整正文或全量聊天记录。

排序依据 Agent 本轮工作完成的时间，不用事项 `updatedAt` 或中途回复落盘时间；改标题、优先级、已读或置顶都不把旧会话顶到最上方。生成期间保留上轮已完成回复的摘要、时间和顺序；`turn/end` 完成后一起发布最后消息段落、完成时间和对应未读。摘要与时间随 `duduSessionActivity` 投影缓存和正常会话事件更新，不为每次刷新重新扫描正文。提问、错误等注意事项不覆盖消息摘要时间。

新增 `board.pin {target, pinned}`，`target` 为 `assistant` 或 `issue:<id>`；使用电脑端 `assistant/chat-home.db` 保存。首次创建默认置顶嘟嘟；用户取消后重启不会重新置顶。

新增 `board.read {target, sessionId, unread, seq?}`，复用服务端已读回执与手动未读标记。清除只提交该行实际拿到的序号，旧操作不能读掉更新的回复；事项重分配后拒绝旧 session 的操作。普通列表、置顶、预加载都不会自动写已读。

原生端每次明确打开会话都开始新的阅读访问，即使复用了同一个 watch 与缓存内容；上一访问的本地去重记录和迟到响应不能阻止新访问确认。这样从主页手动标为未读后，再打开同一会话可以重新确认，实际确认仍要等待最新真实内容可见。该原生返回路径本轮只做源码检查和编译，尚未用真机验证。

App 图标角标统计所有事项范围和嘟嘟中的未读会话，同一 session 只计一次，置顶不重复计数。App 前台通过普通主页刷新更新角标；本次没有增加聊天 APNs 推送或后台保活，不能据此承诺 App 退出后角标也能实时收到新消息。切换电脑清除前一电脑的展示和角标，旧请求不得写入新电脑的数据或阻塞新电脑首次加载。
