## 数据和调度

- `host/assistant/tasks/` 是 dudu 自己的用户任务系统，与 `assistant/schedule/` 的收集器调度分开，也不调用 DSH schedule 插件。只共用现有的 Croner 包装器求下一次时间。
- `<DSH_HOME>/dudu/assistant/tasks.db`：SQLite，WAL，FULL 同步；任务和投递记录分表。版本过新时拒绝打开，不重建数据库。
- 规则：单次、分钟间隔、每天、工作日、每周多日、每月指定日、五段 Cron。时区是明确的 IANA 名称。月末不存在的日期跳过；夏令时按已锁定的 Croner 11 语义。间隔有持久锚点，不因重启漂移。
- 每秒检查到期项；休眠后将错过的重复触发合并为一次，不逐条补发。单次在认领后保留为已结束。
- 认领和下一次时间在同一事务落盘，然后才接触会话；保存具体会话 ID 后才投递。投递有固定的 `dudu-task-<run.id>` 请求标识。进程在投递中断开时标成 `uncertain`，不自动重试可能已经送出的消息。它不是 exactly-once 完成保证；主人可以查看会话后决定是否立即执行。
- `delivering / delivered / failed / uncertain` 表示投递事实，绝不表示 Agent 已完成。记录保留投递时的完整提示词、供应商/模型、规则和会话快照。
- 手动立即执行不移动下一次计划；暂停不取消已投递的任务；删除任务删除其本地记录，不删除会话或撤回消息。复制默认暂停，使用新身份、空运行记录和空的自动复用绑定；明确选择的已有会话目标仍保留。
- 所有编辑带 `revision`；桌面、App 和对话共同使用它，冲突不会覆盖较新的编辑。调度和会话事实不增加编辑版本；异步验证期间发生的运行更新也保留。

## 会话与权限

执行位置：新建对话并复用、每次新建对话、已有会话。工作区必须是 DSH 已登记且仍存在的文件夹；供应商/模型必须是已配置的选择。

新会话先设模型和主人在“设置 › 通用”选择的嘟嘟默认权限，再投递；没有配置时沿用主人已确定的完全访问默认值（2026-11-09），不额外加只读限制。这一版没有新增任务权限选择器。已有会话保留它的权限，且模型必须与任务一致；定时器不会替主人切换正在使用的会话的模型。改变任务的供应商、模型、工作区或执行目标，会解除旧的自动复用绑定；旧记录与会话保留。明确选择已有会话时仍须匹配新的工作区和模型，不匹配则保存报错，主人可改选“新建对话并复用”或其他匹配的已有会话。纯标题/内容修改保留绑定。运行记录另存投递前实际解析出的 provider、model、工作区和新会话权限，不把“默认模型”当作实际模型名称。

仅通过既有 DSH sessionController/workspaceRegistry 和 dudu 的会话适配器操作会话；不接触 harness 协议，不修改 OAR，不修改 DSH 的全局默认模型。任务运行不建事项、不改变事项流程、不向事项 Activity 写自动进展。

## 嘟嘟自己做的任务（2026-11-11）

主人定的（2026-11-11：“选 A，这样改动最小”）：「供应商」列表里加一项「嘟嘟」（排第一，用它自己的图标），表单的行和字都不改名。设计稿在本机 `.local/designs/scheduled-tasks-fresh-session-2026-11-11/`（`form.png` 的 A、`run.png`、`chat.png`；代码绘制，不是运行中的截图）。

- **为什么不在嘟嘟的主对话里跑**：主对话是一条永久的会话（2026-11-10 约 37 万 token，没有自动压缩），任务的过程会把它撑满。每次运行是 DSH 里自己的一个会话：有嘟嘟的身份、记忆、事项摘要、连接器、收集器、工具和技能（系统提示每次重建），没有聊天记录；起步约 8–10 万 token（估计：2026-11-02 实测第一个请求 7.5 万，再加上现在更长的系统提示）。主对话只收到结果：群聊里的一行 `task`（`home/group.mjs`：任务名、时间、正文）；嘟嘟在系统提示的“群聊（资料）”里看得到最近 12 条（任务结果每条最多 2000 字，其他 800 字），所以主人能接着问（“第 3 条展开说说”）。
- **表单**：选了嘟嘟，没有“关联工作区”（嘟嘟在自己的目录 `~/.dsh/dudu/home` 里工作，任务的 `project` 是 null，带来的 project 不保存），“执行位置”只有“新建对话并复用”“每次新建对话”（没有“已有会话”：那等于在主对话里跑）。“模型”留着：嘟嘟的任务能单独选便宜的模型（嘟嘟能用的对话模型，不含 Claude Code 和 Codex），没选就用“设置 › 通用”里嘟嘟对话的模型。新任务选嘟嘟时默认“每次新建对话”；选其他供应商仍是“新建对话并复用”，和以前一样。其他供应商的行和选项不变。
- **每次新建对话**：每次一个会话（id 以 `dudu-assistant-task-` 开头，各种会话列表会略过它）；每个任务保留最近 20 次的会话（运行记录的“打开会话”能打开），更早的收起来（DSH 只能收起，不能删除）。**新建对话并复用**：任务自己的一个会话，用满 24 次（和收集器同一个规则）后换新的、旧的收起来；一次运行出了错，下一次也换新的。`assistant/task-sessions.json` 记着这些；改了供应商、模型或执行位置，引擎忘掉旧绑定，旧会话不再用。
- **一次运行**：引擎只记“投递”（提示词被收下就是 delivered）；之后的等待、读结果、放进聊天、收起会话在 `home/task-session.mjs` 的 `follow` 里。同一个任务的上一次还没结束，下一次等着，不重叠。30 分钟还没结束就叫停并报失败。权限用“设置 › 通用”里的默认权限（默认完全访问）；没有人能批准，所以审批一律拒绝。
- **没话可说就不出声**：这一轮的最后一条消息是 `[SILENT]`（或什么也没写）就不往聊天里放任何东西（例如“每 10 分钟看看有没有要处理的，有就发待办卡片”）；运行有 `show_todo_card`，卡片直接出现在主对话里。出了错或超时，放一行失败（`ok: false`，正文是原因），只说一次；关插件时在跑的运行被取消，不报失败。
- **工具**：和嘟嘟的对话一样，但没有 `tasks_*`（运行时读到的网页不可信，不能因此新建或改任务）；这些会话不记进嘟嘟的记忆（记忆只记主人自己的话）。
- **没做的**：Claude、ChatGPT、DeepSeek 做的任务，结果仍不放进聊天（设计稿 `chat.png` 手机上那条 Claude 的气泡没有做）；删除任务不收起它的会话；运行记录里没有“做完/没做完”，引擎只记投递。
