# Dudu 电脑连接插件

Dudu 电脑连接插件（包名 `dsh-dudu`，插件 id 是 `dudu`；开源之前的私有构建里叫 `dsbot` 或 `dudu`）`0.1.0` 为 SwiftUI iPhone 客户端提供原生会话连接和带鉴权的 HTTP 页面。
发布包 `dudu-desktop-0.1.0.zip` 包含 `dsh-dudu-0.1.0.tgz`。
不声明 DSH 版本约束，升级 DSH 不会仅因版本号变化而被标记为不兼容。

## 安装与配对

1. 在 DSH Desktop「插件」中安装 `dsh-dudu-0.1.0.tgz`；如果装过旧的 `dsbot` 或 `dudu` 插件，请先卸载它。
2. 打开 DSH Desktop「设置 → 手机控制」，填写电脑名称。
3. 添加一个或多个手机可访问的连接地址。
4. 在目标地址旁手动点击「生成二维码」。
5. 手机打开 Dudu，扫码或粘贴完整配对链接；已连接时可在「电脑连接 → 添加电脑」继续配对。

地址不区分局域网与公网模式。配置 TLS 的反向代理或隧道可填写
`https://your-domain.example`，局域网可填写 `http://电脑地址:3170`。
界面与新配对链接不再带 `/dsbot` 后缀；已有带后缀的地址、链接和手机凭据仍可使用，
底层鉴权 API 与页面路径保持不变。
WebView 按用户填写的 HTTP/HTTPS 协议直接加载手机适配页面。
页面固定保留根据当前内网 IP 自动生成的地址，不能修改或删除；
网络变化后自动更新，其他地址仍可自行管理。
添加地址、保存配置或打开页面均不会自动生成配对码。

首次配对码有效 10 分钟。配对成功后保留连接凭据；在电脑端撤销某台手机会断开
其连接，并阻止它再次认证。手机可保存、切换多台电脑。同一台电脑的地址变化后
重新扫码会更新已有记录。

## 手机可使用的会话功能

新任务可从电脑端实际注册的供应商中选择 DeepSeek、Claude 或 ChatGPT，再选择工作区开始。
模型与思考等级按所选供应商筛选，创建接口先应用模型再返回会话，第一条消息使用已选路由。
已有内容的会话沿用原供应商；同一供应商内仍可切换电脑端提供的模型和思考等级。
手机通过现有鉴权接口操作电脑端 DSH 与 OAR。旧版电脑插件没有供应商目录时，
App 继续使用原有模型列表。

侧栏沿用桌面端的彩色 Agent Logo、ChatGPT 光学校正和 `idle / working / blocked` 判断（正常结束、提问和出错都算 blocked）。
打开侧栏时刷新列表，保持打开时每 5 秒安静刷新；关闭侧栏后取消该轮询。
刷新只读会话元数据与已有状态，不运行模型、不生成进度，也不更改事项。

`0.3.3` 起，已认证的手机可以对当前会话执行白名单命令 `/goal`、`/plan`、`/compact`，
把照片和文件作为附件随消息发送，并获得结构化的对话记录（思考、工具调用、用时和用量）。
`0.3.9` 起，手机通过 `session.attachment` 读取当前订阅会话里的图片，支持独立圆角缩略图和全屏预览。
该接口沿用配对鉴权，只接受当前会话的附件引用，不接收任意路径或图片 URL；会话快照不携带图片原始数据。
白名单之外的命令一律拒绝；文件只通过 DSH 自带的上传接口暂存，单个文件不超过 16 MB。
`0.3.4` 起，手机还可以读取模型的推理等级和可用的 Agent 预设（模式），在新会话中选择项目和模式，
并修改当前会话的推理等级；预设只能取自 DSH 返回的列表。
`0.3.5` 起，手机从插件读取 DSH 的侧栏入口、会话视图和设置分区（含图标），
其他插件新增的内容会自动出现在手机上；DSH 窗口把这些内容报告给插件，插件保存最近一份
（`DSH_HOME/dudu/navigation.json`）。升级插件后请打开一次 DSH 窗口，手机才会拿到完整列表。
`0.3.12` 新增 `session.search`，调用 DSH 原生的正文检索接口，返回可见会话和命中片段，不启动会话。

`0.3.13` 为 HTTP 页面脚本和样式增加 gzip 传输。
`0.3.15` 移除手机端资源管理和相关终端、浏览器、工作区文件网页，以及标签同步和终端输入接口。
`0.3.16` 修复设置页面保留后的栏目恢复；插件市场请求失败或切换页面后，不再露出 DSH 首页。
`0.3.17` 同步 DSH 排队消息及编辑、删除、插话操作；订阅目标、任务、计划等实时状态，只将唤起回复的通知显示在对话中。
`0.3.18` 补齐原生对话的文件改动与 diff、交付及生成文件预览、单选／多选／文本问答、模型重试和错误详情、历史分页、工具完整输入输出、消息分支、会话／本轮性能及队列图片。等待中的问答参与 DSH 的同一回答链；电脑和手机任一端回答后，另一端失效。已继续工作的问答使用 DSH 的补答接口。

新接口只服务已鉴权且正在查看的会话。历史与详情以 DSH 的事件序号定位；文件路径从会话中的交付或成功写入事件解析，不接受手机自定义读取路径。文件及 diff 单次响应上限为 16 MiB（DSH 自身可能采用更小的文件限制）；工具文本按页读取，保留完整内容。历史摘要和 diff 依赖 DSH 仍保有对应修改记录。
`0.3.6` 起，会话列表带上 DSH 的归档、置顶和每个工作区里的顺序，并支持重命名工作区、删除工作区的登记
和取消归档；设置里不再列出「通用设置」。
`0.3.8` 起，会话详情带上 DSH 的任务清单（`todos`，只读：内容和状态）；手机可以置顶、取消置顶和归档会话（`session.pin`、`session.archive`，对应 DSH 的 `workspace/pinSession`、
`unpinSession`、`archiveSession`，不带「停止运行中的工作」选项：有任务在跑时 DSH 会拒绝，要在电脑上确认）；
DSH 没有删除会话的接口，插件也不提供；用到遮罩、裁剪、渐变等 SVG 特性的侧栏图标，
DSH 窗口会把它渲染成 64×64 的小图再传输，插件校验 PNG 文件头和尺寸，单个不超过 16 KB。
旧版 App 或旧版插件缺少这些方法时会自动退回到原有的纯文本对话。

## 公网入口

将 `/dsbot` 及其子路径转发到安装插件的电脑 `3170` 端口。
原生会话使用 `/dsbot/api/v1/` 下的鉴权 HTTP API 和事件长轮询；复杂页面使用
`/dsbot/web/open` 和 `/dsbot/ui/` 下的 HTTP 请求。无需转发 DSH 网页、
`/api/` 或其他路径。未鉴权的页面、资源及操作不会被提供。

HTTPS 使用系统证书验证。原生 API 和网页会话的打开请求均通过 Authorization
请求头携带配对凭据。请求 URL 和网页脚本
均不携带配对密钥。网页文档、资源和操作使用独立且仅适用于该页面的
HttpOnly Cookie。认证后仅允许限定的业务方法，不提供任意 HTTP 或 DSH RPC 代理。
反向代理会终止 TLS，中转服务器可以接触解密后的流量。

App 与插件只通过 HTTP/HTTPS 通信，不使用 WebSocket Upgrade。旧版配对链接中的
WS/WSS scheme 只会在 App 导入时归一化为 HTTP/HTTPS；新地址请填写 HTTP 或 HTTPS。

插件会验证配置地址是否到达这台电脑，再签发配对码。安装包不包含个人域名、
证书、托管中继或预置电脑地址。与其他服务共用一个域名时，
为 `/dsbot` 及其子路径设置独立路由即可，其他服务保持自己的路由。

## 维护与升级

电脑需要保持 DSH 和连接隧道运行。配置和设备记录保存在
`DSH_HOME/dudu/`，默认 `~/.dsh/dudu/`。从 `dsbot` 升级时，首次启动会复制原 `DSH_HOME/dsbot/`
里的已配对设备和设置，旧目录保留。重启或升级保留已有记录，
设备密钥以散列形式保存。

macOS 上从源码更新可在仓库运行 `npm run desktop:update`，自动打包、通过 Desktop
自带的 CLI 安装并请求热重载。脚本核对本地运行回执中的版本和代码指纹，并探测
服务就绪；热重载失败会报告原因并保持 DSH 打开，不会自动重启。
`npm run desktop:install` 使用同样的热更新流程。只有加 `-- --restart` 才会主动退出并
重新打开 DSH；DSH 自己的退出确认仍然有效，脚本不会强制杀进程。
从 DSH 里运行的任务（Claude、Codex 会话）里更新会被自保护拒绝，因为热重载会拆掉所有运行中会话的适配器；
确实要这样更新时加 `-- --force`，那些会话（包括运行它的那个）会被切断。
更新日志、结果和 profile 备份在 `.local/desktop-updates/`。
安装包路径包含源码指纹，同版本修改也会安装新的包，避免包管理器复用旧缓存。
更新脚本只在 profile patch 中替换自己的构建注释，不改变已有配置值。DSH 按文件内容
判断是否重新组合插件，单纯修改文件时间戳不会生效。

已在 Desktop 自带 CLI 的隔离 web 环境验证前后端同时热更新：DSH PID 和浏览器文档
保持不变，事项和布局保留。后端重载仍会释放供应商实例，尚不支持保留正在执行的
harness 轮次。更新脚本会在安装前检查进程祖先，阻止由该 Desktop 托管的 Agent
在自己的工作轮次中触发默认热更新，避免下一步出现 `NO_ADAPTER`。
这种情况下源码已经打包，任务结束后从 Desktop 之外的终端运行更新命令即可。

上游错误分类保存在 `DSH_HOME/dudu/diagnostics/upstream.jsonl`，自动轮转，
只记录接口、失败阶段和错误码，不记录请求参数、会话正文或凭据。

从旧版升级时，手机使用原 bundle identifier 覆盖安装，保留 Keychain 和数据。
旧凭据只在实际认证时按迁移规则导入；撤销后的旧凭据不能再次导入。
旧的网页中继不再通过公网转发，也不打包进此插件。

此包仅包含电脑插件。手机 App 需通过适用的 Apple 签名、TestFlight 或
App Store 分发。Windows 和 Linux 的电脑端安装尚未实机验证。
